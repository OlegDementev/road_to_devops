## Мониторинг и процессы <a id="t_7.0"></a>
### Обзор системы <a id="t_7.1"></a>
Прежде чем разбираться с процессами, нужно понять общее состояние системы.  
- Нагружена ли она?  
- Хватает ли памяти?  
- Есть ли место на диске?

#### uptime [uptime] <a id="t_7.1.1"></a>
Команда `uptime` показывает текущее время, длительность работы системы, количество активных пользователей и среднюю нагрузку за 1, 5 и 15 минут.

```bash
uptime [OPTION]...

[OPTION]:
-p, --pretty     — выводить время работы в удобочитаемом формате
-s, --since      — показать дату и время запуска системы

[EXAMPLE]:
uptime           # стандартный вывод: время, аптайм, пользователи, нагрузка
uptime -p        # только время работы в красивом виде
uptime -s        # время запуска системы

# Вывод команды uptime
18:25:30 up 12 min,  2 users,  load average: 0,03, 0,06, 0,06
```

**Load average** — это среднее количество процессов, которые ждут CPU или находятся в непрерываемом сне (обычно ждут диск). Грубо говоря — сколько задач «толпится» у процессора.

Как читать:
| Значение | Что означает |
|:----|:---|
|Меньше числа ядер | Всё спокойно, процессор простаивает  |
|Равно числу ядер  | Система загружена ровно на 100%      |
|Больше числа ядер | Процессы ждут очереди, есть проблема |

Узнать число ядер можно командой `nproc`.  
Если у тебя 4 ядра и `load average = 8` — система перегружена вдвое.  
Если у тебя 4 ядра и `load average = 0.5` — загрузка около 12%.  
Если 1-минутное значение высокое, а 15-минутное низкое — система только что получила всплеск нагрузки.  
Если наоборот — нагрузка спала.

#### free [display amount of free and used memory] <a id="t_7.1.2"></a>
Команда `free` показывает количество свободной и используемой оперативной памяти (RAM), а также области подкачки (swap) в системе.

```bash
free [OPTION]...

[OPTION]:
-h, --human      — выводить в удобочитаемом формате (КБ, МБ, ГБ)
-m               — выводить в мегабайтах
-g               — выводить в гигабайтах
-t, --total      — добавить итоговую строку (Total)
-s N, --seconds=N — обновлять вывод каждые N секунд
-w, --wide       — разделить кэш на buffers и cache (широкий формат)
-c N, --count=N  — выполнить N обновлений (используется с -s)

[EXAMPLE]:
free                 # память в килобайтах (по умолчанию)
free -h              # в удобочитаемом виде (МБ/ГБ)
free -m              # в мегабайтах
free -g              # в гигабайтах
free -t              # показать итоговую строку
free -s 2            # обновлять каждые 2 секунды
free -h -s 5 -c 3    # 3 обновления с интервалом 5 секунд

free -h
#               total        used        free      shared  buff/cache   available
# Mem:           7.7Gi       2.1Gi       3.2Gi       123Mi       2.4Gi       5.1Gi
# Swap:          2.0Gi          0B       2.0Gi
```
| Колонка | Значение |
|:----|:---|
| total | Всего памяти | 
| used | Использовано | 
| free | Полностью свободно | 
| shared | Разделяемая память (tmpfs, shm) | 
| buff/cache | Кэш файлов и буферы ядра | 
| available | Реально доступно для новых процессов | 

**Важно**: смотри на `available`, а не на `free`. Linux использует свободную память под кэш диска — это нормально. Если `free` маленький, но `available` большой — всё в порядке. Кэш отдаётся под процессы, как только они его попросят.

**swap** — раздел подкачки на диске. Если он активно используется (колонка used растёт) — системе не хватает RAM, и она тормозит. Небольшое использование swap — норма. Постоянное — тревожный сигнал.

#### df [disk free] <a id="t_7.1.3"></a>
Команда `df` показывает информацию об использовании дискового пространства для смонтированных файловых систем: общий объём, занятое и свободное место, точку монтирования. 

```bash
df [OPTION]... [FILE]...

[OPTION]:
-h, --human-readable — выводить размеры в удобочитаемом формате (КБ, МБ, ГБ)
-T, --print-type     — показать тип файловой системы
-i, --inodes         — показать информацию об inode вместо блоков
-a, --all            — включить все файловые системы, включая псевдо
-x, --exclude-type=TYPE — исключить файловые системы указанного типа
-t, --type=TYPE      — показать только файловые системы указанного типа
--total              — добавить итоговую строку
-l, --local          — показывать только локальные файловые системы

[EXAMPLE]:
df                   # использование диска в килобайтах
df -h                # в удобочитаемом виде (МБ/ГБ)
df -h /              # только для корневой файловой системы
df -T                # с указанием типа файловой системы
df -i                # использование inode
df -h --total        # с итоговой строкой
df -h -x tmpfs       # исключить tmpfs
df -h -t ext4        # только ext4

df -h
# Filesystem      Size  Used Avail Use% Mounted on
# /dev/sda1        50G   18G   30G  38% /
# /dev/sda2       200G   45G  145G  24% /home
# tmpfs           3.9G     0  3.9G   0% /dev/shm
```

#### du [disk usage] <a id="t_7.1.4"></a>
Команда `du` оценивает и выводит размер дискового пространства, занимаемого файлами и директориями (рекурсивно, включая поддиректории).  
`df` говорит, сколько занято всего. `du` — кто именно занимает.

```bash
du [OPTION]... [FILE]...

[OPTION]:
-h, --human-readable — выводить размеры в удобочитаемом формате (КБ, МБ, ГБ)
-s, --summarize      — выводить только итоговый размер для каждой директории
-a, --all            — учитывать не только директории, но и все файлы
-c, --total          — добавить итоговую строку (Total)
-d N, --max-depth=N  — ограничить глубину вывода N уровнями
--exclude=PATTERN    — исключить файлы, соответствующие шаблону
-x, --one-file-system — не переходить на другие файловые системы

[EXAMPLE]:
du -sh /var/log                 # итоговый размер директории /var/log
du -h --max-depth=1 /home       # размер каждой поддиректории в /home
du -ah /etc                     # все файлы и директории в /etc с размерами
du -sh *                        # размер каждого элемента в текущей директории
du -ch *.log                    # размер всех .log + итоговая строка
du --exclude='*.tmp' -sh /tmp   # размер /tmp без .tmp файлов
```
`du` может не совпадать с `df`. Если файл открыт процессом, но удалён, место не освобождается, пока процесс не закроет дескриптор. `df` это место видит, `du` — уже нет.

### Что такое процесс <a id="t_7.2"></a>
Процесс — это запущенная программа. Программа на диске — это просто файл. Пока её не запустили, она ничего не делает. Как только ядро загрузило её в память и начало исполнять — это процесс.

У каждого процесса есть **PID (Process ID)** — уникальный номер. По нему система отличает один процесс от другого. Посмотреть процессы текущей сессии можно командой `ps`.

#### ps [process status] <a id="t_7.2.1"></a>
Команда `ps` выводит информацию о запущенных в системе процессах: их PID, состояние, использование ресурсов, команду запуска и другие атрибуты.

```bash
ps [OPTION]...

[OPTION]:
-e, -A           — показать все процессы
-f               — полный формат вывода (UID, PID, PPID, время старта, команда)
-u USER          — процессы указанного пользователя
-aux             — все процессы в BSD-стиле (часто используется)
-ef              — все процессы в полном формате (System V-стиль)
-o FORMAT        — задать свои столбцы (например, pid,ppid,cmd)
--sort=KEY       — сортировка по столбцу (например, -%mem, %cpu)
-p PID           — показать только процесс с указанным PID

[EXAMPLE]:
ps                       # процессы текущего терминала
ps -ef                   # все процессы в полном формате
ps aux                   # все процессы в BSD-стиле
ps -u john               # процессы пользователя john
ps -eo pid,ppid,cmd      # свои столбцы: PID, PPID, команда
ps aux --sort=-%mem      # все процессы, сортировка по памяти (по убыванию)
ps -p 1234               # информация о процессе с PID 1234

ps
#     PID TTY          TIME CMD
#    4521 pts/0    00:00:00 bash
#    4530 pts/0    00:00:00 sleep
```

#### PPID: родительский процесс <a id="t_7.2.2"></a>
Процессы не появляются из ниоткуда. Каждый процесс создаётся другим процессом — своим родителем. У процесса-родителя есть свой `PID`, у ребёнка — ссылка на него, `PPID (Parent PID)`.

```bash
ps -o pid, ppid, cmd
#     PID    PPID CMD
#    4521    4390 -bash
#    4530    4521 sleep 100
```

Здесь `sleep (PID 4530)` запущен из `bash (PID 4521)`.  
А сама `bash` запущена процессом `4390` — это может быть терминал, SSH-сессия или что-то ещё.

Посмотреть дерево процессов:
```bash
pstree -p
# systemd(1)─┬─NetworkManager(712)─┬─...
#            ├─sshd(845)───sshd(4102)───bash(4521)───sleep(4530)
#            └─cron(890)
```

Вся система сходится к одному процессу — `PID 1`.  В современных Ubuntu это `systemd`. Он запускается ядром при загрузке и порождает всё остальное.

#### fork и exec <a id="t_7.2.3"></a>
Когда процесс хочет запустить другую программу, он делает это в два шага:

+ `fork()` — создаёт свою копию. Получается два почти одинаковых процесса: родитель и ребёнок. Ребёнок получает новый `PID`.

+ `exec()` — заменяет содержимое процесса новой программой. После этого процесса-ребёнка уже не отличить от той программы, которую запустили.

Почему в два шага, а не одним? Потому что между `fork` и `exec` можно настроить окружение ребёнка: перенаправить потоки (`>`, `|`), поменять переменные, сменить пользователя. Именно так работает `sudo`: форкается, настраивает права, потом делает `exec` целевой команды.

#### Состояния процесса <a id="t_7.2.4"></a>
В `ps` есть колонка `STAT` — состояние процесса. Основные значения:

```bash
tolkonemen9i@ubuntu2404:~$ ps -eo pid,stat,cmd | head
    PID STAT CMD
      1 Ss   /sbin/init splash
      2 S    [kthreadd]
      3 S    [pool_workqueue_release]
      4 I<   [kworker/R-rcu_gp]
      5 I<   [kworker/R-sync_wq]
      6 I<   [kworker/R-kvfree_rcu_reclaim]
      7 I<   [kworker/R-slub_flushwq]
      8 I<   [kworker/R-netns]
     11 I<   [kworker/0:0H-events_highpri]
```
| Код | Состояние | Что означает |
|:-------|:-------|:-------|
| R | Running / Runnable    | Выполняется или ждёт процессор
| S | Sleeping              | Ждёт события (ввод, таймер, сеть)
| D | Uninterruptible sleep | Ждёт диск, нельзя прервать сигналом
| T | Stopped               | Остановлен (Ctrl+Z, kill -STOP)
| Z | Zombie                | Завершился, но родитель ещё не забрал код возврата
| I | Idle | Бездействующий поток ядра (kernel thread). Используется для оптимизации энергопотребления, в отличие от D не увеличивает показатель Load Average.

Дополнительные символы рядом с буквой:
| Символ | Значение |
|:-------|:-------|
| < | Высокий приоритет (процесс имеет отрицательное значение nice, забирает больше процессорного времени).
| N | Низкий приоритет (процесс имеет положительное значение nice, уступает время другим).
| s | Лидер сессии (процесс создал новую сессию, часто это системные службы или оболочки вроде bash).
| l | Многопоточный (процесс имеет несколько потоков выполнения, например, современные браузеры или базы данных).
| + | В foreground-группе (процесс запущен на переднем плане и закреплен за текущим терминалом).


#### Зомби и сироты <a id="t_7.2.5"></a>
**Зомби (Z)** — процесс уже завершился, но родитель ещё не вызвал `wait()` и не забрал его код возврата. Ядро держит запись в таблице процессов, пока родитель не заберёт.

Зомби не занимают память и CPU — только строчку в таблице. Проблема возникает, если их накапливаются тысячи: таблица процессов переполняется, и система не может создать новые процессы.

Убить зомби нельзя — он уже мёртв. Убить можно только родителя, тогда зомби перейдёт к PID 1, который сразу заберёт код возврата. Или нужно исправить программу-родителя.

**Сирота** — противоположный случай: процесс жив, а родитель умер. Ядро автоматически «усыновляет» сироту — делает родителем PID 1. Так работают демоны: запустились, отвязались от терминала и живут сами.

#### Потоки <a id="t_7.2.6"></a>
Один процесс может содержать несколько потоков (threads). Потоки — это параллельные линии исполнения внутри одного процесса. Они делят общую память, но имеют свои стеки и регистры.  
С точки зрения управления (сигналы, приоритеты) поток не отличается от процесса — но это уже тема для более глубокого изучения. На уровне новичка достаточно знать, что один процесс может быть многопоточным, и это нормально.

### Просмотр процессов <a id="t_7.3"></a>
#### ps [process status] <a id="t_7.3.1"></a>
Команда `ps` выводит информацию о запущенных в системе процессах: PID, состояние, использование ресурсов, команду запуска и другие атрибуты.

```bash
ps [OPTION]...

[OPTION]:
-e, -A           — показать все процессы
-f               — полный формат вывода (UID, PID, PPID, время старта, команда)
-u USER          — процессы указанного пользователя
-aux             — все процессы в BSD-стиле (часто используется)
-ef              — все процессы в полном формате (System V-стиль)
-o FORMAT        — задать свои столбцы (например, pid,ppid,cmd)
--sort=KEY       — сортировка по столбцу (например, -%mem, %cpu)
-p PID           — показать только процесс с указанным PID

[EXAMPLE]:
ps                       # процессы текущего терминала
ps -ef                   # все процессы в полном формате
ps aux                   # все процессы в BSD-стиле
ps -u john               # процессы пользователя john
ps -eo pid,ppid,cmd      # свои столбцы: PID, PPID, команда
ps aux --sort=-%mem      # все процессы, сортировка по памяти (по убыванию)
ps -p 1234               # информация о процессе с PID 1234

ps aux
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1 167436 11856 ?        Ss   Jan10   0:04 /sbin/init
root       712  0.0  0.2 312480 20480 ?        Ssl  Jan10   0:12 NetworkManager
oleg      4521  0.0  0.1  22456  5120 pts/0    Ss   14:28   0:00 -bash
oleg      4530  0.0  0.0   8084   524 pts/0    S    14:32   0:00 sleep 100

ps -ef
UID        PID  PPID  C STIME TTY          TIME CMD
root         1     0  0 Jan10 ?        00:00:04 /sbin/init
oleg      4521  4390  0 14:28 pts/0    00:00:00 -bash
oleg      4530  4521  0 14:32 pts/0    00:00:00 sleep 100

ps aux | grep nginx                           # найти процессы nginx
ps -eo pid,ppid,cmd --sort=-%cpu | head       # топ по CPU
ps -eo pid,user,%mem,cmd --sort=-%mem | head  # топ по памяти
ps -u oleg                                    # все процессы пользователя oleg
ps -p 4521 -o pid,ppid,cmd,stat               # информация о конкретном PID

| Колонка | Значение |
|:--------|:-------|
| USER    | Владелец процесса
| PID     | ID процесса
| PPID    | ID родительского процесса (Parent ID)
| %CPU    | Загрузка CPU
| %MEM    | Доля RAM
| VSZ     | Виртуальная память (КБ)
| RSS     | Реальная память в RAM (КБ)
| TTY     | Терминал (? — нет терминала, демон)
| STAT    | Состояние
| START   | Время запуска
| TIME    | Суммарное CPU-время
| COMMAND | Команда
```

#### top [display Linux processes] и htop <a id="t_7.3.2"></a>
Команда `top` отображает в реальном времени динамическую информацию о запущенных процессах: загрузку CPU, использование памяти, список процессов с возможностью сортировки и управления.  
`htop` — улучшенная версия `top`. Цветная, с псевдографикой, мышью, горизонтальной прокруткой


```bash
top [OPTION]...

[OPTION]:
-d SECONDS       — интервал обновления (по умолчанию 3 секунды)
-n N             — выполнить N обновлений и завершиться (пакетный режим)
-p PID[,PID...]  — отслеживать только указанные PID
-u USER          — показывать процессы только указанного пользователя
-b               — пакетный режим (вывод в файл, без интерактива)
-H               — показывать потоки (threads)
-o FIELD         — сортировать по указанному полю (например, -o %MEM)
-i               — не показывать idle-процессы

[EXAMPLE]:
top                     # запустить в интерактивном режиме
top -d 1                # обновлять каждую секунду
top -u john             # только процессы пользователя john
top -p 1234             # только процесс с PID 1234
top -b -n 1 > top.txt   # один снимок в файл (пакетный режим)
top -o %MEM             # сортировать по использованию памяти
top -H                  # показать потоки

top -d 1 -n 1 -b | head -n 30  # обновлять раз в секунду, показать топ-20:
```
Дале представлена полная расшифровка вывода команды `top`.

```bash
tolko_ne_pc@DESKTOP-C991MI9:~$ top

Tasks:  53 total,   1 running,  52 sleeping,   0 stopped,   0 zombie

      7 root      20   0    3072   1792   1792 S   0.0   0.0   0:00.00 init
     40 root      19  -1   42096  15616  14720 S   0.0   0.1   0:00.08 systemd-journal
```

**Строка 1: Общая информация о системе**  
`top - 22:28:52 up 0 min,  1 user,  load average: 0.00, 0.00, 0.00`

* **`22:28:52`** — Текущее системное время.
* **`up 0 min`** — Время непрерывной работы системы (Uptime). Система была перезагружена или включена менее минуты назад.
* **`1 user`** — Количество авторизованных в системе пользователей на данный момент.
* **`load average: 0.00, 0.00, 0.00`** — Средняя загрузка системы за последние 1, 5 и 15 минут соответственно. Значения `0.00` означают, что за это время процессор абсолютно не испытывал нагрузки и не имел очередей из задач.

**Строка 2: Статистика процессов (Tasks)**  
`Tasks:  53 total,   1 running,  52 sleeping,   0 stopped,   0 zombie`

* **`53 total`** — Всего процессов зарегистрировано в оперативной памяти.
* **`1 running`** — Количество процессов, выполняющихся в данный момент или готовых к выполнению (активное состояние). Как правило, это сама утилита `top`.
* **`52 sleeping`** — Процессы в состоянии ожидания (сна). Они ждут определенного события (ввода пользователя, сетевого пакета, системного таймера) и не тратят ресурсы CPU.
* **`0 stopped`** — Остановленные процессы (например, через сигналы остановки вроде `Ctrl+Z`).
* **`0 zombie`** — Процессы-зомби. Это завершенные процессы, которые уже освободили ресурсы, но их родительский процесс еще не прочитал код завершения.

**Строка 3: Использование ресурсов процессора (%Cpu)**  
`%Cpu(s):  0.0 us,  0.6 sy,  0.0 ni, 99.4 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st`  
*Показывает распределение времени процессора в процентах:*

* **`0.0 us`**  (*user*): Время, затраченное на процессы пользователей с обычным приоритетом.
* **`0.6 sy`**  (*system*): Время, затраченное ядром ОС и системными вызовами. Наблюдается минимальная активность ядра при старте.
* **`0.0 ni`**  (*nice*): Время на пользовательские процессы с измененным приоритетом (положительным значением nice).
* **`99.4 id`** (*idle*): Процент времени, в течение которого процессор бездействует. **Процессор свободен на 99.4%**.
* **`0.0 wa`**  (*iowait*): Время ожидания завершения операций ввода-вывода (например, чтения/записи на диск). Значение `0` говорит об отсутствии дисковых задержек.
* **`0.0 hi`**  (*hardware interrupts*): Время на обработку аппаратных прерываний.
* **`0.0 si`**  (*software interrupts*): Время на обработку программных прерываний.
* **`0.0 st`**  (*steal time*): Время, «украденное» гипервизором у этой виртуальной машины в пользу других ВМ (актуально для облачных серверов). `0.0` означает, что деления ресурсов с соседями нет.

**Строка 4: Оперативная память (MiB Mem)**  
`MiB Mem :  15538.2 total,  14705.3 free,    606.3 used,    420.4 buff/cache`
*Все значения указаны в мибибайтах (MiB):*

* **`15538.2 total`** — Общий объем физической оперативной памяти в системе (около 15 ГБ).
* **`14705.3 free`** — Объем полностью свободной памяти, которая ничем не занята.
* **`606.3 used`** — Объем памяти, используемый программами и операционной системой в данный момент.
* **`420.4 buff/cache`** — Память, выделенная под буферы ядра и кэш страниц диска для ускорения повторного доступа к файлам. При необходимости система мгновенно освобождает её для нужд приложений.

**Строка 5: Память подкачки (MiB Swap) и доступность памяти**  
`MiB Swap:   4096.0 total,   4096.0 free,      0.0 used.  14931.8 avail Mem`
*Все значения указаны в мибибайтах (MiB):*

* **`4096.0 total`** — Общий размер файла/раздела подкачки (Swap) на диске (4 ГБ).
* **`4096.0 free`** — Объем свободного пространства в Swap.
* **`0.0 used`** — Объем Swap, занятый данными. Значение `0` указывает на то, что физической памяти хватает с избытком, и сброс данных на диск не требуется.
* **`14931.8 avail Mem`** — Количество памяти, реально **доступное** для запуска новых приложений без ухода системы в Swap (рассчитывается как `free` + часть `buff/cache`, которую можно безболезненно очистить).

**Таблица процессов**
Каждая строка под заголовками описывает конкретную задачу (процесс), запущенную в системе.

| Поле        | Описание |
| :---------- | :--- |
| **PID**     | Идентификатор процесса (Process ID). Уникальный номер для управления процессом. |
| **USER**    | Имя пользователя, от лица которого запущен процесс (в данном примере везде `root`). |
| **PR**      | Приоритет планирования процесса с точки зрения ядра (от -20 до +19 или `rt` для реального времени). Чем ниже число, тем выше приоритет. |
| **NI**      | Значение `nice` (от -20 до 19). Пользовательская корректировка приоритета. `0` — стандартный приоритет. |
| **VIRT**    | Виртуальный объем памяти (Virtual Image). Общий объем памяти, который процесс затребовал у ОС, включая код, данные, разделяемые библиотеки и выделенные, но еще не используемые области. |
| **RES**     | Резидентная память (Resident Size). Реальный объем физической оперативной памяти (RAM), который процесс занимает в данный момент. |
| **SHR**     | Разделяемая память (Shared Mem). Часть памяти процесса, которая может быть потенциально использована другими программами (например, общие системные библиотеки). |
| **S**       | Статус процесса. Основные варианты: `S` (sleeping — спит), `R` (running — выполняется), `D` (uninterruptible sleep — непрерывно спит, ждет диск). |
| **%CPU**    | Процент процессорного времени, используемый процессом с момента последнего обновления. |
| **%MEM**    | Процент физической оперативной памяти (RAM), используемый процессом (рассчитывается от `RES`). |
| **TIME+**   | Суммарное процессорное время, затраченное на процесс с момента его старта (в формате `минуты:секунды.сотые`). |
| **COMMAND** | Имя команды или исполняемого файла, который запустил процесс. |

**Разбор запущенных процессов**

1. **PID 1 (`systemd`)**: 
   * Первый процесс в системе (диспетчер системы и служб). 
   * Потребляет **12.3 МиБ** реальной памяти (`RES`), имеет стандартный приоритет (`PR 20`, `NI 0`), находится в спящем режиме (`S`), ожидая системных событий.
2. **PID 2 (`init-systemd`)** и **PID 7 (`init`)**:
   * Компоненты инициализации (характерно для подсистем вроде WSL или контейнеров). 
   * Потребляют минимум памяти (около **1.8 МиБ**) и не используют процессор.
3. **PID 40 (`systemd-journal`)**:
   * Системная служба ведения логов (журналирования). 
   * Занимает **15.6 МиБ** оперативной памяти. Работает с чуть более высоким приоритетом ядра (`PR 19`), чтобы гарантированно успевать записывать системные сообщения.

#### pgrep <a id="t_7.3.3"></a>
Команда `pgrep` ищет процессы в системе по имени и другим атрибутам, выводя их `PID` (идентификаторы процессов).

```bash
pgrep [OPTION]... PATTERN

[OPTION]:
-l               — показывать имя процесса вместе с PID
-a               — показывать полную командную строку вместе с PID
-f               — искать по всей командной строке, а не только по имени
-u USER          — искать процессы указанного пользователя
-x               — точное совпадение имени процесса
-n               — показать только самый новый (последний запущенный) процесс
-o               — показать только самый старый процесс
-c               — вывести только количество найденных процессов
-P PPID          — искать процессы с указанным родительским PID
-t TERM          — искать процессы, привязанные к указанному терминалу

[EXAMPLE]:
pgrep ssh                  # найти PID процессов ssh
pgrep -l ssh               # PID + имя процесса
pgrep -a ssh               # PID + полная командная строка
pgrep -u john              # процессы пользователя john
pgrep -f "python script"   # поиск по всей командной строке
pgrep -x bash              # точное совпадение имени bash
pgrep -n ssh               # PID самого нового процесса ssh
pgrep -c ssh               # количество процессов ssh
pgrep -P 1                 # процессы с родительским PID 1
```

#### pkill <a id="t_7.3.4"></a>
Команда `pkill` посылает сигнал процессам, отобранным по имени и другим атрибутам (аналогично pgrep, но с отправкой сигнала). 

```bash
pkill [OPTION]... PATTERN

[OPTION]:
-SIGNAL          — послать указанный сигнал (например, -9, -15, -HUP)
-f               — искать по всей командной строке, а не только по имени
-u USER          — только процессы указанного пользователя
-x               — точное совпадение имени процесса
-n               — послать сигнал только самому новому процессу
-o               — послать сигнал только самому старому процессу
-P PPID          — только процессы с указанным родительским PID
-t TERM          — только процессы, привязанные к указанному терминалу

[EXAMPLE]:
pkill ssh                  # завершить все процессы ssh (SIGTERM)
pkill -9 chrome            # принудительно убить все процессы chrome
pkill -f "python script"   # убить по полной командной строке
pkill -u john              # завершить все процессы пользователя john
pkill -x bash              # точное совпадение имени bash
pkill -n ssh               # завершить только самый новый ssh
pkill -HUP nginx           # послать SIGHUP процессам nginx
pkill -P 1                 # завершить процессы с родительским PID 1
```

#### pidof [find the process ID of a running program] <a id="t_7.3.4"></a>
Команда `pidof` находит PID (идентификаторы процессов) запущенных программ по их имени.

```bash
pidof [OPTION]... PROGRAM...

[OPTION]:
-s               — вывести только один PID (самый новый)
-o PID           — исключить указанный PID из результата
-x               — также находить PID скриптов, запущенных через интерпретатор

[EXAMPLE]:

pidof -x script.sh         # PID скрипта script.sh
```

### Сигналы и управление <a id="t_7.4"></a>
*Сигнал* — это короткое уведомление, которое ядро доставляет процессу. Программа может его поймать и обработать, а может проигнорировать. Некоторые сигналы игнорировать нельзя. Сигналы нужны для управления процессами: попросить завершиться, приостановить, перезапустить конфиг.

**Как это работает под капотом?**  
У каждого процесса в `Linux` есть встроенный «слушатель» сигналов. Когда сигнал поступает, у программы есть три пути:
+ **Выполнить действие по умолчанию:** например, завершить работу при получении `SIGTERM`.
+ **Перехватить сигнал (Пользовательская обработка):** программист может написать в коде: «Если пришел сигнал, сначала выполни логику, потом обработай сигнал.».
+ **Игнорировать сигнал:** большинство сигналов можно просто пропустить мимо ушей.

**Исключение из правил: SIGKILL (9)**  
Сигнал `SIGKILL` перехватить или проигнорировать нельзя. Программа даже не узнает, что он ей пришел, потому что ядро `Linux` уничтожает процесс в обход самой программы.  

#### kill [send a signal to a process] <a id="t_7.4.1"></a>
Команда `kill` отправляет сигнал указанному процессу по его `PID`. Команда `kill` не «убивает» — она отправляет сигнал. Имя историческое, потому что чаще всего отправляют именно сигнал завершения. По умолчанию посылает SIGTERM (15), который просит процесс завершиться корректно. Сигнал SIGKILL (9) принудительно завершает процесс.

Хотя в системе существует `более 60 сигналов`, на практике чаще всего используются следующие:

| Сигнал | Номер | Можно перехватить? | Описание и применение |
| :--- | :---:  | :---: | :--- |
| **`SIGHUP`**  | 1 | **Да** | **Сигнал отбоя (Hangup)**. Исторически отправлялся при закрытии терминала. Сегодня используется для **перезапуска/перезагрузки конфигурационных файлов** демонов (например, Nginx, Apache) без их остановки. |
| **`SIGINT`**  | 2 | **Да** | Прерывание с клавиатуры (`Ctrl + C`). Корректно останавливает процесс. |
| **`SIGQUIT`** | 3 | **Да** | Выход с дампом памяти (`Ctrl + \`). Используется для отладки зависших приложений. |
| **`SIGKILL`** | 9 | ❌ **Нет** | **Немедленное уничтожение**. Ядро завершает процесс мгновенно. Программа не успевает сохранить данные. |
| **`SIGUSR1`** | 10 | **Да** | Пользовательский сигнал №1. Часто используется для ротации логов или перечитывания конфигов. |
| **`SIGUSR2`** | 12 | **Да** | Пользовательский сигнал №2. Применяется разработчиками для кастомных задач. |
| **`SIGTERM`** | 15 | **Да** | **Сигнал по умолчанию** для команды `kill`. Вежливая просьба к программе завершить работу. |
| **`SIGCHLD`** | 17 | **Да** | Отправляется родительскому процессу, когда его дочерний процесс завершает работу. |
| **`SIGCONT`** | 18 | **Да** | **Возобновление работы**. Размораживает процесс после сигналов `SIGSTOP` или `SIGTSTP`. |
| **`SIGSTOP`** | 19 | ❌ **Нет** | **Замораживание процесса**. Ядро приостанавливает выполнение приложения (процесс не тратит CPU). |


```bash
kill [-s signal | -signal] PID...
kill -l [signal]

[OPTION]:
-s SIGNAL, --signal SIGNAL — указать сигнал по имени или номеру
-SIGNAL                    — альтернативная форма (например, -9, -TERM)
-l, --list                 — вывести список всех сигналов

[EXAMPLE]:
kill 1234                     # послать SIGTERM процессу 1234
kill -15 1234                 # то же самое
kill -9 1234                  # принудительно убить
kill -SIGKILL 1234            # по имени сигнала

kill -l                       # список всех сигналов
kill -l 9                     # узнать имя сигнала по номеру
kill -s TERM 1234 5678        # послать SIGTERM двум процессам

# У многих демонов SIGHUP означает «перечитай конфигурационный файл, не завершаясь». Это позволяет менять настройки без перезапуска.
# Не все демоны это поддерживают. Смотреть нужно в документации конкретного сервиса. В systemd-мире чаще используется systemctl reload
kill -1 $(cat /var/run/nginx.pid)      # перечитать конфиг nginx
kill -HUP 1234                         # то же для PID 1234 по имени сигнала
```

#### killall [kill processes by name] <a id="t_7.4.2"></a>
Команда `killall` отправляет сигнал всем процессам с указанным именем. По умолчанию посылает SIGTERM (15). В отличие от kill, работает не по PID, а по имени процесса. `killall` без точного имени может убить лишнее. Имя чувствительно к регистру.

```bash
killall [OPTION]... NAME...

[OPTION]:
-s SIGNAL, --signal SIGNAL — указать сигнал (по имени или номеру)
-9, -KILL                  — принудительное завершение (SIGKILL)
-i, --interactive          — запрашивать подтверждение перед завершением
-q, --quiet                — не выводить сообщения, если процесс не найден
-v, --verbose              — сообщать, что сигнал отправлен
-u USER, --user USER       — завершать только процессы указанного пользователя
-e, --exact                — точное совпадение имени (иначе совпадение по подстроке)
-I, --ignore-case          — игнорировать регистр имени
-w, --wait                 — ждать завершения всех убитых процессов

[EXAMPLE]:
killall firefox                  # завершить все процессы firefox (SIGTERM)
killall -9 chrome                # принудительно убить все chrome
killall -s HUP nginx             # послать SIGHUP nginx (перечитать конфиг)
killall -u john                  # завершить все процессы пользователя john
killall -i bash                  # спросить подтверждение перед завершением bash
killall -v ssh                   # показать, какие процессы ssh завершены
killall -e ssh                   # точное совпадение имени ssh
```


#### pkill [signal processes based on name and other attributes] <a id="t_7.4.3"></a>
Команда `pkill` отправляет сигнал процессам, отобранным по имени и другим атрибутам (аналогично `pgrep`, но с отправкой сигнала). По умолчанию посылает SIGTERM (15).

```bash
pkill [OPTION]... PATTERN

[OPTION]:
-SIGNAL          — послать указанный сигнал (например, -9, -15, -HUP)
-f               — искать по всей командной строке, а не только по имени
-u USER          — только процессы указанного пользователя
-x               — точное совпадение имени процесса
-n               — послать сигнал только самому новому процессу
-o               — послать сигнал только самому старому процессу
-P PPID          — только процессы с указанным родительским PID
-t TERM          — только процессы, привязанные к указанному терминалу

[EXAMPLE]:
pkill ssh                  # завершить все процессы ssh (SIGTERM)
pkill -9 chrome            # принудительно убить все процессы chrome
pkill -f "python script"   # убить по полной командной строке
pkill -u john              # завершить все процессы пользователя john
pkill -x bash              # точное совпадение имени bash
pkill -n ssh               # завершить только самый новый ssh
pkill -HUP nginx           # послать SIGHUP процессам nginx
pkill -P 1                 # завершить процессы с родительским PID 1
```

#### Как убить процесс, который не убивается <a id="t_7.4.4"></a>
Если `kill -9` не работает, причины обычно такие:

+ **Процесс в состоянии `D`**. Ждёт ядро (диск, NFS, сеть). Сигналы не доставляются. Помогает только перезагрузка или устранение причины на уровне железа/сети.
+ **Процесс — зомби `Z`**. Убить нельзя, он уже мёртв. Нужно убить родителя или дождаться, пока родитель заберёт код возврата.
+ **Это процесс ядра**. Они в квадратных скобках в `ps`, у них нет пользовательской памяти. Убить их нельзя — только выгрузить модуль или перезагрузиться.
+ **У тебя нет прав**. Процесс принадлежит другому пользователю или `root`. Нужен `sudo`.
+ **Процесс — PID 1**. `systemd` не убивается из соображений безопасности ядра. Это защита от случайного краха системы.
