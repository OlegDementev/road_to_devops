## Заголовки <a id="t_2.0.0"></a>
Заголовков может быть 6 уровней.

Альтернативный синтаксис для заголовков первого и второго уровня:
```md
Заголовок 1
===

Заголовок 2
---
```

Лучшая практика: всегда оставлять пустую строку перед заголовком (кроме начала файла) и одну после него. На GitHub заголовки автоматически становятся якорями для навигации.

## Выделение текста <a id="t_4.0.0"></a>

- *Курсив* или _курсив_
- **Жирный** или __жирный__
- ***Жирный курсив*** или ___жирный курсив___
- ~~Зачёркнутый текст~~
- `Моноширинный (код) внутри строки`
- Комбинации: **жирный и _курсив_ внутри**

В чистом Markdown нет <u>подчеркнутого текста</u>, только через HTML тег `<u>`

Выделение цветом не поддерживается Markdown в чистом виде, но HTML-тег `<mark>` <mark> поддерживается</mark>.

Цвет текста (ограниченная поддержка, лучше избегать, но иногда работает):
<span style="color:red;">Красный текст</span> — может работать в просмотре README, но не в <span style="color:green;">мобильной</span> версии и не во всех <span style="color:yellow;">контекстах</span>. <font color="#e32c66">Лучше полагаться</font> на семантические теги.

## Списки <a id="t_5.0.0"></a>

### Ненумерованные <a id="t_5.1.0"></a>

- Элемент 1
- Элемент 2
  - Вложенный элемент (2 пробела или табуляция)
  - Ещё вложенный
- Элемент 3

Можно использовать `*`, `-` или `+`. Рекомендуется придерживаться одного стиля.

### Нумерованные <a id="t_5.2.0"></a>

1. Первый пункт
2. Второй пункт
   1. Вложенный нумерованный (3 пробела перед цифрой)
   2. Второй вложенный
3. Третий пункт

Номера можно ставить и так (рендерится корректно):
1. Первый
1. Второй
1. Третий

### Смешанные списки <a id="t_5.3.0"></a>

1. Пункт
   - Вложенный ненумерованный
   - Ещё один
2. Пункт
   * Вложенный
     1. Глубокий вложенный

## Блоки кода и комментарии <a id="t_9.0.0"></a>

Подсветка `bash`
```bash
#!/bin/bash
echo "Hello, Linux!"
```
Подсветка `diff`

```diff
- удалённая строка
+ добавленная строка
@@ контекст @@
```

Подсветка `md`
```md
<!-- Комментарий в стиле HTML-->
[comment]: # (Комментарий в стиле Markdown)
[//]: # (Комментарий в стиле Markdown)
[^_^]: # "Невидимый комментарий с смайликом"
```

## Поддержка HTML <a id="t_12.0.0"></a>
Markdown изначально задумывался как удобный синтаксис для преобразования в HTML. Поэтому почти все HTML-теги можно использовать прямо внутри Markdown-документа. Это позволяет расширять возможности разметки там, где средства самого Markdown недостаточны.
