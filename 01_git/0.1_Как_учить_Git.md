## Как учить Git
**Git** — это не просто программа, это «магия», которая пугает новичков. Кажется, что запомнить все эти команды (`rebase`, `cherry-pick`, `stash`) невозможно. Но правда в том, что 99% времени вы будете использовать всего 5 команд. Главное — правильный подход к обучению.

## Что такое GitHub, GitLab, Bitbucket?
+ **Git** — это инструмент (программа), который живет на вашем компьютере. Он отслеживает изменения в файлах. Это «движок».
+ **GitHub / GitLab / Bitbucket** — это **хостинги** (сайты) для Git-репозиториев. Это «облачные хранилища» для вашего кода, где удобно работать в команде.

### Краткий обзор платформ
+ **GitHub:** Самый популярный. Здесь лежит open-source (открытый код) всего мира. Если вы хотите показать себя работодателю — ваш профиль должен быть здесь.
+ **GitLab:** Мощный конкурент. Славится своим встроенным CI/CD (автоматизация сборки и тестов). Часто используется в крупных компаниях для приватного кода.
+ **Bitbucket:** Продукт от Atlassian (создателей Jira). Удобен, если компания уже пользуется их экосистемой. Раньше был популярен для бесплатных приватных репозиториев.

## Один хороший тренажер
Теория без практики мертва. Но ставить Git на компьютер и ломать терминал страшно. Поэтому используйте тренажеры.  
[Learn Git Branching](https://learngitbranching.js.org/?locale=ru_RU&NODEMO=). Это легендарный интерактивный тренажер. Вы вводите команды и визуально видите, как двигаются ветки и коммиты. Это лучший способ понять, как работает `merge` и `rebase`. Пройдите его до конца. Это займет пару вечеров, но даст 80% необходимых навыков.

## Создайте свой GitHub или GitLab
Это самый важный шаг. Без своего репозитория навык не закрепится.  

+ Заведите аккаунт на **GitHub** и/или **GitLab**.
+ Создайте первый репозиторий. Неважно, что это будет: скрипт для сортировки файлов или просто текстовая заметка.
+ Синхронизируйте свой репозиторий в облаке со своим компьютером.
+ Сделайте несколько коммитов, отмените один из них.
+ Попробуйте создать новую ветку, а затем слить их в одну.
+ Попробуйте сделать «Pull Request» (или Merge Request) в свой же проект. Это имитация реальной работы в команде.

## Итог
Не бойтесь Git. Пройдите два курса, поиграйте в тренажер, зарегистрируйтесь на GitHub и залейте туда свой «Hello World». Как только вы сделаете первый `push` в свою ветку, страх исчезнет, и вы поймете, что это просто удобный инструмент.
