Глава 6. Магия текстовой обработки: потоки, конвейеры и фильтры
6.1. Введение: почему текст — это главное в Linux
Основные моменты:

Философия Unix: «всё есть файл», «одна программа — одна задача», «программы общаются через текст».

Где это нужно на практике: анализ логов (/var/log/), фильтрация вывода команд, работа с CSV и конфигами, подготовка данных.

Ключевая идея главы: не заучивать команды по отдельности, а научиться собирать их в цепочки.

Краткий recap из главы 4: напомнить про stdin (0), stdout (1), stderr (2) и символ |. Сошлись на главу 4, чтобы не дублировать.

6.2. Конвейер (pipe) — главный инструмент главы
Основные моменты:

Что такое | и как он работает: stdout левой команды → stdin правой команды.

Аналогия: конвейер на заводе, где каждая команда — это станок.

Важное правило: pipe передаёт только stdout, stderr идёт мимо (если не перенаправить отдельно).

Практика: ls -l | less, cat file | wc -l, ps aux | grep bash.

Частая ошибка новичка: пытаться использовать pipe там, где команда и так принимает файл как аргумент (cat file | grep vs grep pattern file).

6.3. Разведка и просмотр: cat, nl, wc, head, tail
Основные моменты:

cat — не только «показать файл», но и склейка файлов (cat a.txt b.txt > c.txt), и cat -n / cat -A (показать непечатаемые символы).

nl — нумерация строк (и чем отличается от cat -n).

wc — -l, -w, -c, -m; как считать строки в потоке.

head / tail — -n, а главное: tail -f для живого мониторинга логов. Это must-have.

Практический сценарий: посмотреть, что происходит в логе прямо сейчас: tail -f /var/log/syslog.

6.4. Поиск по тексту: grep (ключевой инструмент)
Основные моменты:

Базовый синтаксис: grep "pattern" file.

Ключевые опции: -i (игнор регистра), -v (инвертировать), -r (рекурсивно), -n (номер строки), -c (только счётчик), -l (только имена файлов), -w (слово целиком), -A/-B/-C (контекст вокруг совпадения).

Регулярные выражения: ., *, ^, $, [], \ — только база, без глубокого погружения в regex.

grep -E (расширенные regex) и egrep — когда нужны +, ?, |.

Отличие grep от egrep/fgrep.

Практический сценарий: найти все ошибки в логе: grep -i "error" /var/log/syslog.

6.5. Колонки и поля: cut и awk
Основные моменты:

cut — простой инструмент для вырезания колонок:

-d (разделитель), -f (номер поля), -c (по символам).

Пример: cut -d: -f1 /etc/passwd — получить список пользователей.

awk — мощный инструмент, который заслуживает отдельного внимания:

Базовый синтаксис: awk '{print $1}' file.

Как awk видит строку: $0 — вся строка, $1, $2... — поля, $NF — последнее поле.

Разделитель полей: -F и переменная FS.

Условия: awk '$3 > 100 {print $1}'.

Встроенные переменные: NR (номер строки), NF (количество полей).

Пример: awk -F: '{print $1, $3}' /etc/passwd — пользователи и их UID.

Сравнение: когда cut, а когда awk. cut проще и быстрее, awk гибче.

Практический сценарий: вытащить IP-адреса из лога веб-сервера.

6.6. Сортировка и подсчёт: sort и uniq
Основные моменты:

sort — -n (числовая), -r (обратная), -k (по колонке), -u (убрать дубли), -t (разделитель).

uniq — -c (счётчик), -d (только дубли), -u (только уникальные).

Важно: uniq работает только с отсортированными данными, поэтому всегда sort | uniq, а не наоборот.

Классическая связка: sort | uniq -c | sort -rn — топ самых частых записей.

Практический сценарий: посчитать, сколько раз каждый IP заходил на сервер: cut -d' ' -f1 access.log | sort | uniq -c | sort -rn | head.

6.7. Замена и трансформация: tr, expand, unexpand
Основные моменты:

tr — замена символов: tr 'a-z' 'A-Z', tr -d (удалить), tr -s (сжать повторы).

expand / unexpand — табы ↔ пробелы. Зачем это нужно (выравнивание в отчётах, работа с legacy-файлами).

Практический сценарий: привести текст к верхнему регистру: cat file | tr 'a-z' 'A-Z'.

6.8. Объединение и разделение: paste, join, split, tee
Основные моменты:

paste — склеить файлы по колонкам (горизонтально, в отличие от cat).

join — SQL-подобное соединение двух файлов по общему полю. Показать простой пример.

split — разрезать большой файл на части (-l по строкам, -b по байтам).

tee — «тройник»: вывод и на экран, и в файл одновременно. Незаменим при отладке конвейеров.

Практический сценарий: command | tee output.log | grep "Error" — сохранить всё и сразу отфильтровать.

6.9. Собираем всё вместе: разбор «убийственной» команды
Основные моменты:

Взять пример: cat file.log | grep "Error" | cut -d' ' -f1 | sort | uniq -c.

Разобрать по шагам:

cat file.log — читаем файл.
grep "Error" — оставляем только строки с ошибками.
cut -d' ' -f1 — берём первое поле (например, дату или IP).
sort — сортируем для uniq.
uniq -c — считаем повторы.
Показать, как это можно улучшить: добавить sort -rn | head, чтобы получить топ-10.

Показать альтернативу на awk: awk '/Error/ {print $1}' file.log | sort | uniq -c — короче и элегантнее.

Объяснить, почему это работает и как читать такие цепочки.
