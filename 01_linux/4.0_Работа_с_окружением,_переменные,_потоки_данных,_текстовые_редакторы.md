## Работа с окружением, переменные, потоки данных, текстовые редакторы <a id="t_4.0"></a>
В операционной системе Linux переменные делятся на два ключевых класса: **локальные переменные оболочки** и **переменные окружения**. Они представляют собой именованные области памяти, которые хранят информацию о настройках пользовательской сессии, системной среды и параметрах работы программ.  

Внутри терминала запускается командная оболочка — это программа, которая читает ваши команды, интерпретирует их и передаёт ядру. По умолчанию во многих дистрибутивах Linux используется **Bash** (Bourne Again SHell).  
Текущая оболочка — это та копия Bash, в которой вы сейчас находитесь и вводите команды. Она уникальна для каждого конкретного окна или вкладки терминала.

Когда вы запускаете внешнюю команду, происходит следующее:
+ Текущая оболочка (процесс-родитель) получает вашу команду (например, `ls`).
+ Она создаёт копию своего процесса (процесс-ребёнок) через системный вызов `fork()`.
+ В этом новом процессе дочерняя оболочка замещает себя исполняемым файлом программы `ls` через вызов `exec()`.

**Важно:** Процесс-ребёнок наследует переменные окружения родителя, но любые изменения внутри дочернего процесса никак не могут повлиять на родительскую оболочку.

**Локальная переменная оболочки:**
```bash
MY_VAR="world"
# Создаётся в памяти текущего процесса оболочки.
# Не попадает в глобальное окружение (не видна через env или printenv).
# Не передаётся дочерним процессам и запускаемым скриптам.
# Доступна как для чтения, так и для изменения внутри текущей оболочки.
```

**Экспортированная переменная (Переменная окружения):**
```bash
export MY_VAR="world"
# Добавляется в окружение текущей оболочки.
# Становится доступна через команды env и printenv.
# Автоматически наследуется всеми дочерними процессами и скриптами.
```

### Переменные окружения <a id="t_4.1"></a>
**Переменные окружения** — это именованные значения, которые хранят глобальную конфигурацию пользовательской сессии и системной среды. Они напрямую влияют на логику работы запускаемых процессов и утилит.  

**Где они используются:**
* Указывают операционной системе перечень директорий для поиска исполняемых файлов (`PATH`).
* Определяют текущую локализацию и язык интерфейса (`LANG`, `LC_ALL`).
* Идентифицируют активного пользователя и его окружение (`USER`, `HOME`, `SHELL`).
* Задают системные предпочтения по умолчанию для текстовых редакторов (`EDITOR`) или пейджеров (`PAGER`).

**Области применения и роль переменных:**  

* **Управление конфигурацией:** Настройка поведения ПО без необходимости изменять или перекомпилировать исходный код.
* **Динамическая адаптация:** Программы гибко меняют логику работы, считывая переменные окружения «на лету».
* **Передача параметров:** Удобный способ прозрачного обмена информацией между независимыми сценариями и утилитами.
* **Повторное использование:** Глобальные данные хранятся централизованно в одном месте, исключая хардкод в скриптах.

#### Классификация переменных по уровням сохранения и видимости <a id="t_4.1.1"></a>

| Категория переменных | Область действия | Где хранятся / Как создаются |
| :--- | :--- | :--- |
| **Локальные переменные** | Только текущий процесс оболочки. Исчезают при закрытии вкладки терминала. | Создаются вручную синтаксисом `NAME=value` (без пробелов вокруг `=`). В конфигурационные файлы не записываются. |
| **Пользовательские переменные окружения** | Действуют для конкретного пользователя во всех его сессиях. Наследуются дочерними процессами. | Прописываются через ключевое слово `export` в файлах домашней директории: `~/.bashrc` (для интерактивных терминалов) или `~/.bash_profile` / `~/.profile` (для сессий входа, например, по SSH). |
| **Системные (глобальные) переменные окружения** | Доступны абсолютно всем пользователям системы и любым системным службам. | Файлы конфигурации:<br>• `/etc/environment` (принимает строго пары `КЛЮЧ=значение`, без команды export).<br>• `/etc/profile` (для логин-сессий).<br>• Скрипты с расширением `.sh` внутри директории `/etc/profile.d/`. |

### Основные команды управления переменными окружения <a id="t_4.2"></a>
Краткая сводка команд по работе с переменными окружения, далее они будут разбираться подробнее:

```bash
echo $NAME               # Вывести значение переменной NAME на экран
echo $HOME               # Вывести путь к домашней директории текущего пользователя
echo $PATH               # Вывести список путей для поиска исполняемых файлов
echo $USER               # Вывести имя текущего пользователя

NAME="value"             # Создать локальную переменную оболочки
NAME=                    # Очистить значение переменной (переменная становится пустой)
export NAME="value"      # Создать переменную окружения (экспортировать)

env | grep PATH          # Найти переменные окружения, содержащие подстроку "PATH"
env или printenv         # Отобразить список всех доступных переменных окружения
env -i bash              # Запустить чистый экземпляр bash без наследования текущего окружения

unset NAME               # Полностью удалить переменную из памяти текущей сессии
```

#### env [run a program in a modified environment] <a id="t_4.2.1"></a>
Команда запускает указанную программу с изменённым окружением. Без аргументов выводит все Команда настраивает окружение для запуска конкретной программы. Если вызывать без аргументов, она выведет весь список текущих переменных окружения.

```bash
env [OPTION]... [COMMAND [ARG]...]

[OPTION]:
-i, --ignore-environment — полностью очистить окружение перед запуском команды
-u NAME, --unset=NAME   — удалить конкретную переменную NAME из передаваемого окружения
-0, --null              — разделять строки вывода нулевым байтом (ASCII NUL) вместо новой строки
-S STRING               — разобрать строку аргументов для корректной обработки внутри скриптов

[EXAMPLE]:
env                        # Вывести все переменные окружения
env -i bash                # Запустить bash с абсолютно пустым окружением
env -u HOME bash           # Запустить оболочку, скрыв от неё переменную HOME
env MYVAR=value ./script.sh # Передать временную переменную MYVAR только на время работы script.sh
env -i PATH=/bin ls        # Запустить ls в изолированном окружении, где определен только PATH
```

#### printenv [print environment] <a id="t_4.2.2"></a>
Команда `printenv` выводит переменные окружения. В отличие от `env`, она умеет выводить точечные значения конкретных переменных, переданных в качестве аргументов.

```bash
printenv [OPTION]... [VARIABLE]...

[OPTION]:
-0, --null     — завершать строки вывода нулевым символом (безопасно для xargs -0)

[EXAMPLE]:
printenv                 # Вывести все переменные окружения (аналогично env)
printenv HOME            # Вывести только значение переменной HOME (без знака $)
printenv PATH SHELL      # Вывести значения PATH и SHELL построчно
```

#### export [export environment variables] <a id="t_4.2.3"></a>
Встроенная команда оболочки, которая помечает локальную переменную как экспортируемую, превращая её в переменную окружения для дочерних процессов.

```bash
export [OPTION]... [NAME[=VALUE]]...

[OPTION]:
-p               — вывести список всех экспортированных переменных текущей сессии
-n               — убрать переменную из глобального окружения, вернув ей статус локальной
-f               — экспортировать указанное имя NAME как функцию оболочки

[EXAMPLE]:
export PATH="/usr/local/bin:$PATH"   # Добавить каталог в начало PATH и экспортировать изменения
export EDITOR=nano                   # Сделать текстовый редактор nano системным по умолчанию
export -n EDITOR                     # Исключить EDITOR из окружения (останется локальной)
export -p                            # Показать все экспортированные переменные оболочки
```

#### unset [unset values and attributes] <a id="t_4.2.4"></a>
Встроенная команда для полного удаления переменных или функций из оперативной памяти текущего сеанса оболочки.

```bash
unset [-f] [-v] [-n] [NAME...]

[OPTION]:
-f               — удалять исключительно функцию с именем NAME
-v               — удалять переменную (применяется автоматически по умолчанию)
-n               — удалить переменную-ссылку (nameref), не затрагивая целевую переменную

[EXAMPLE]:
unset MYVAR                 # Полностью удалить переменную MYVAR из памяти сессии
unset -f myfunc             # Удалить функцию оболочки с именем myfunc
unset PATH                  # Удалить системный PATH (сломает поиск команд в текущей сессии)
```

### Переменная окружения PATH <a id="t_4.3"></a>
Когда вы вводите короткое имя команды (например, `ls` или `python3`), система не знает, где физически находится этот файл. Она начинает поочередно искать его в каталогах, перечисленных в переменной `PATH`. Поиск выполняется строго **слева направо** до первого совпадения.

```bash
# Посмотреть текущие пути поиска:
echo $PATH
# Выведет строку вида: /usr/local/bin:/usr/bin:/bin:/usr/games

# Временное добавление своего каталога в PATH (только для текущего терминала):
export PATH=/my/custom/bin:$PATH   # Добавление в приоритетный запуск (в начало)
export PATH=$PATH:/my/custom/bin   # Добавление в низкоприоритетный запуск (в конец)
```
**Важно:** Элементы в `PATH` разделяются исключительно двоеточием (`:`). Не рекомендуется включать туда пути с пробелами или относительные пути (например, `.`), так как это снижает безопасность системы.

### Постоянное изменение переменных окружения <a id="t_4.4"></a>
Чтобы переменные не сбрасывались после закрытия терминала или перезагрузки, их декларацию сохраняют в конфигурационных файлах.

| Конфигурационный файл | Момент выполнения | Сфера применения |
| :--- | :--- | :--- |
| `~/.bashrc` | При открытии любого нового окна/вкладки терминала (Non-login shell). | Текущий пользователь. |
| `~/.bash_profile` | Выполняется один раз при входе в систему (Login shell, SSH-сессия). | Текущий пользователь. |
| `~/.profile` | Выполняется при авторизации, если отсутствует файл `~/.bash_profile`. | Текущий пользователь. |
| `/etc/environment` | Считывается системным менеджером PAM при старте сессии (до запуска оболочки). | Глобально для всех пользователей. |
| `/etc/profile` | Выполняется один раз при входе любого пользователя в систему. | Глобально для всех пользователей. |

Применение изменений без перезагрузки системы выполняется при перелогине в систему или командой:

```bash
# После редактирования любого файла нужно выполнить
source /путь/к/файлу
```

#### source [execute commands from a file in the current shell] <a id="t_4.4.1"></a>
Команда `source` (или её синоним — точка `.`) заставляет текущую командную оболочку прочитать и выполнить инструкции из указанного файла прямо в рамках своего процесса, не порождая дочерний `fork()`. Это незаменимо для моментального применения обновленных конфигураций.

```bash
source FILENAME [ARGUMENTS...]
. FILENAME [ARGUMENTS...]

[OPTION]:
Нет стандартных ключей. Файл может принимать аргументы, которые становятся позиционными параметрами внутри выполняемого скрипта.

[EXAMPLE]:
source ~/.bashrc                     # перезагрузить .bashrc в текущей сессии
. ~/.bashrc                          # то же самое, сокращённая форма
source ./script.sh                   # выполнить скрипт в текущей оболочке
source ./setenv.sh                   # загрузить переменные окружения из скрипта
source myfile.sh arg1 arg2           # выполнить с аргументами
```

### Удаление переменных окружения <a id="t_4.5"></a>
Методология полного избавления от переменных:
1. **Для временного удаления** в текущей сессии введите: `unset NAME`.
2. **Для перманентного удаления** откройте конфигурационный файл, в котором вы сохраняли переменную (`~/.bashrc`, `/etc/environment` и т.д.), физически удалите строку с ней и сохраните изменения. 
3. Чтобы изменения зафиксировались в текущем терминале после правки файлов, выполните сначала `unset NAME`, а затем обновите конфигурацию с помощью `source`.

### Стандартный поток ввода и вывода данных <a id="t_4.6"></a>
У каждого процесса автоматически открыты три файловых дескриптора.  

`stdin` (стандартный ввод) и `stdout` (стандартный вывод) — это два основных потока данных в Linux (и других Unix-подобных системах), которые используются для взаимодействия программы с окружением.

* stdin (файловый дескриптор 0) — поток, из которого программа читает входные данные. По умолчанию — это клавиатура.

* stdout (файловый дескриптор 1) — поток, в который программа выводит свои результаты. По умолчанию — это терминал (экран).

* stderr (файловый дескриптор 2) — отдельный поток для сообщений об ошибках. По умолчанию — тоже экран, но его можно перенаправить независимо от stdout.

Команда `ls` пишет список файлов в `stdout` → вы видите его на экране.  
Если `ls` не может прочитать каталог, ошибка уходит в `stderr` → тоже на экран, но смешиваться с обычным выводом.

### Перенаправление потоков данных <a id="t_4.7"></a>
Используя символы `<, >, >>, |` можно изменить стандартные потоки.  
Для примера есть файл `main.py`, если при запуске ввести не верное имя, будет ошибка.

| Оператор | Действие                                           | Пример                         |
|:--------:|:-------------------------------------------------- |:-------------------------------|
| >        | Перенаправить `stdout` в файл (перезапись)         | python3 main.py > out.txt      |
| >>       | Добавить `stdout` в конец файла                    | python3 main.py >> out.txt     |
| <        | Взять `stdin` из файла                             | python3 main.py < data.txt     |
| 2>>      | Перенаправить `stderr` в конец файла               | python3 main.py 2>> err.txt    |
| &>       | Перенаправить и `stdout`, и `stderr`               | python3 main.py &> other.txt   |
| &>>      | Перенаправить и `stdout`, и `stderr` в конец файла | python3 main.py &> other.txt   |
| \|       | Передать `stdout` одной как `stdin` другой         | ls \| grep ".txt"              |

```bash
wc -l < file.txt  # программа wc считает строки не с клавиатуры, а из file.txt
echo Hello > message.txt  # вместо экрана строка попадёт в файл message.txt
# cat читает файл и пишет в stdout, grep читает из своего stdin (а это будет stdout от cat, т.к используем конвейер) и выводит только строки с "error", less принимает это и показывает постранично
cat /var/log/syslog | grep error | less
# все сообщения об ошибках отправляются "в никуда", видим только успешные результаты. /dev/null — «чёрная дыра»: всё, что туда направлено, исчезает.
find / -name "foo" 2>/dev/null 
```
