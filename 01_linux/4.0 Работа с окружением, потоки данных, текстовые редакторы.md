## Работа с окружением, потоки данных, текстовые редакторы <a id="t_4.0"></a>
Внутри терминала запускается оболочка — это программа, которая читает ваши команды, интерпретирует их и передаёт ядру. По умолчанию в Linux это Bash (Bourne Again SHell).  
Текущая оболочка — это та копия Bash, в которой вы сейчас сидите и печатаете команды. Она уникальна для этого конкретного окна терминала.

Когда вы запускаете команду, происходит следующее:

+ Текущая оболочка (родитель) получает вашу команду (например, `ls`).
+ Она создаёт новый процесс (ребёнка) через системный вызов `fork()`.
+ В этом новом процессе оболочка запускает программу `ls` через `exec()`.

Важно:
+ Ребёнок наследует окружение родителя, но изменения ребёнка не влияют на родителя.

Локальная переменная:
```bash
MY_VAR="world"
# Создаётся в памяти текущей оболочки.
# Не попадает в список переменных окружения (не видна через env или printenv).
# Не передаётся дочерним процессам.
# Доступна только для чтения внутри текущей оболочки.
```

Экспортированная переменная:
```bash
export MY_VAR="world"
# Добавляется в окружение текущей оболочки (становится частью среды).
# Видна через env или printenv.
# Передаётся всем дочерним процессам.
```

### Переменные окружения <a id="t_4.1"></a>
Переменные окружения — это именованные значения, которые хранят информацию о настройках пользовательской сессии и системной среды. Они влияют на поведение процессов и оболочки (shell).  

Где используются:

+ Указывают программам, где искать файлы `PATH`.
+ Определяют язык интерфейса `LANG`.
+ Хранят имя текущего пользователя `USER`.
+ Задают параметры для компиляторов, редакторов и других утилит.

Роль переменных окружения:  

+ Хранение и обработка данных — контейнеры в памяти для значений.
+ Динамическая адаптация — программы меняют поведение в зависимости от значений.
+ Улучшение читаемости кода — осмысленные имена вместо «магических чисел».
+ Повторное использование — данные хранятся в одном месте, ссылки на них многократны.
+ Передача параметров — обмен информацией между частями программы.
+ Управление конфигурацией — настройка поведения ПО без правки исходного кода.

Типы переменных окружения:  
|Тип | Область действия | Где хранятся / как создаются |
|:---|:---|:---|
| Локальные              | Только текущая сессия; исчезают при выходе                    | Создаются командой `export NAME=value` вручную в терминале. Не записываются в файлы. Можно сохранить сессию через утилиту `screen`.
| Пользовательские       | Для конкретного пользователя, сохраняются между сессиями      | Прописываются в `~/.bashrc` (для локального входа) или `~/.bash_profile` (для SSH). Если `.bash_profile` нет, система ищет `.bash_login` или `.profile`.
| Глобальные (системные) | Для всех пользователей системы независимо от типа подключения | Файлы: `/etc/environment, /etc/bash.bashrc` (для локальных сессий всех пользователей), `/etc/profile` (для удалённых сессий всех пользователей).

### Основные команды управления переменными окружения <a id="t_4.2"></a>
Краткая сводка команд по работе с переменными окружения, далее они будут разбираться подробнее:

```bash
echo $NAME               # Вывести значение переменной NAME
echo $HOME               # Домашняя папка
echo $PATH               # Где ищутся исполняемые файлы команд
echo $USER               # Имя пользователя

NAME=value               # Создать локальную переменную
NAME= (пустое значение)  # Быстро очистить значение (но переменная остаётся).
export NAME=value        # Создать экспортированную переменную

env | grep PATH          # Если нужно найти переменную
env или printenv         # Посмотреть все переменные
env -i bash              # Запустить новый shell без наследования текущих переменных

unset NAME               # Удалить переменную.
```

#### env [run a program in a modified environment] <a id="t_4.2.1"></a>
Команда запускает указанную программу с изменённым окружением. Без аргументов выводит все текущие переменные окружения.

```bash
env [OPTION]... [COMMAND [ARG]...]

[OPTION]:
-i, --ignore-environment — запустить команду с пустым окружением
-u NAME, --unset=NAME   — удалить переменную NAME из окружения
-0, --null              — завершать строки вывода нулевым символом (для xargs -0)
-S STRING               — разобрать строку с аргументами (использовать как шелл-строку)

[EXAMPLE]:
env                        # вывести все переменные окружения
env -i bash                # запустить bash с пустым окружением
env -u HOME bash           # запустить bash без переменной HOME
env MYVAR=value ./script.sh # установить MYVAR и запустить script.sh
env -i PATH=/bin ls        # с пустым окружением и только PATH установленным
```

#### printenv [print environment] <a id="t_4.2.2"></a>
Команда printenv выводит значения переменных окружения. Если указаны имена переменных, выводит только их значения (по одному на строку). Без аргументов выводит все переменные окружения.

```bash
printenv [OPTION]... [VARIABLE]...

[OPTION]:
-0, --null     — завершать строки нулевым символом (для безопасной обработки с xargs -0)

[EXAMPLE]:
printenv                 # показать все переменные окружения
printenv HOME            # вывести значение переменной HOME
printenv PATH SHELL      # вывести значения PATH и SHELL
```

#### export [export environment variables] <a id="t_4.2.3"></a>
Команда помечает переменную для передачи в окружение дочерних процессов (т.е. делает её переменной окружения). Без аргументов выводит все экспортированные переменные.

```bash
export [OPTION]... [NAME[=VALUE]]...

[OPTION]:
-p               — вывести все экспортированные переменные (по умолчанию)
-n               — удалить переменную из окружения (отменить экспорт)
-f               — рассматривать NAME как функцию (экспорт функций)

[EXAMPLE]:
export PATH="/usr/local/bin:$PATH"   # добавить каталог в PATH и экспортировать
export EDITOR=nano                   # установить и экспортировать переменную EDITOR
export -n EDITOR                     # удалить EDITOR из окружения
export -p                            # показать все экспортированные переменные
```

#### unset [unset values and attributes] <a id="t_4.2.4"></a>
Команда удаляет переменные, функции или ссылки (nameref) из текущей оболочки, освобождая их значения.

```bash
unset [-f] [-v] [-n] [NAME...]

[OPTION]:
-f               — удалить функцию с указанным именем
-v               — удалить переменную (по умолчанию, если не указано -f)
-n               — удалить ссылку (nameref), а не саму переменную, на которую она ссылается

[EXAMPLE]:
unset MYVAR                 # удалить переменную MYVAR
unset -f myfunc             # удалить функцию myfunc
unset PATH                  # удалить переменную PATH (будьте осторожны)
```

### Переменная окружения PATH <a id="t_4.3"></a>
Когда вы вводите `ls` или `python`, система ищет исполняемый файл в каталогах, перечисленных в переменной окружения `PATH`. Порядок важен: сначала просматриваются каталоги слева направо.

```bash
# Просмотр текущего PATH
echo $PATH
# /usr/local/bin:/usr/bin:/bin:/usr/games

# Добавление своего каталога в PATH (временно для текущей сессии):
export PATH=/my/custom/bin:$PATH   # добавляем в начало
export PATH=$PATH:/my/custom/bin   # добавляем в конец

# Чтобы добавить навсегда, пропишите эту строку в файле ~/.bashrc (или ~/.profile).
# Важно: $PATH — это строка, разделённая двоеточиями. Не включайте в неё каталоги, содержащие пробелы или небезопасные файлы.

# Чтобы переменная сохранялась навсегда, добавьте `export MYVAR=...` в файл `~/.bashrc` или `~/.profile`.
export MYVAR=hello   # задать переменную для текущей сессии
echo $MYVAR          # прочитать
```

### Постоянное изменение переменных окружения <a id="t_4.4"></a>
Чтобы переменные сохранялись после перезапуска терминала, их нужно добавить в конфигурационные файлы оболочки.
| Файл   | Когда загружается  | Для кого  |
|:---:|:----|:----|
| ~/.bashrc | Каждый раз при запуске интерактивной оболочки (новый терминал) | Конкретного пользователя
| ~/.profile | При входе в систему (логин) | Конкретного пользователя
| ~/.bash_profile | При входе в систему (логин) — имеет приоритет над .profile | Конкретного пользователя
| /etc/environment | Системный файл для всех пользователей | Всех пользователей
| /etc/profile | Системный файл для всех пользователей (логин-оболочки) | Всех пользователей

Применение изменений без перезагрузки системы выполняется при перелогине в систему или командой:

```bash
# После редактирования любого файла нужно выполнить
source /путь/к/файлу
```

#### source [execute commands from a file in the current shell] <a id="t_4.4.1"></a>
Команда source (или .) читает и выполняет команды из указанного файла в текущей оболочке, а не в дочернем процессе. Это позволяет изменять переменные окружения, функции и алиасы в текущей сессии.

```bash
source FILENAME [ARGUMENTS...]
. FILENAME [ARGUMENTS...]

[OPTION]:
Нет стандартных ключей. Файл может принимать аргументы, которые становятся позиционными параметрами внутри выполняемого скрипта.

[EXAMPLE]:
source ~/.bashrc                     # перезагрузить .bashrc в текущей сессии
. ~/.bashrc                          # то же самое, сокращённая форма
source ./script.sh                   # выполнить скрипт в текущей оболочке
source ./setenv.sh                   # загрузить переменные окружения из скрипта
source myfile.sh arg1 arg2           # выполнить с аргументами
```

### Удаление переменных окружения <a id="t_4.5"></a>
Удаление переменных:  

+ Для локальной — `unset NAME`.
+ Для пользовательской или глобальной — удалить соответствующую строку из всех файлов, где она прописана, и затем применить `source` для этих файлов. Либо использовать `unset` в текущей сессии, но после перезапуска `shell` переменная восстановится, если осталась в файлах.

### Стандартный поток ввода и вывода данных <a id="t_4.6"></a>
У каждого процесса автоматически открыты три файловых дескриптора.  

`stdin` (стандартный ввод) и `stdout` (стандартный вывод) — это два основных потока данных в Linux (и других Unix-подобных системах), которые используются для взаимодействия программы с окружением.

* stdin (файловый дескриптор 0) — поток, из которого программа читает входные данные. По умолчанию — это клавиатура.

* stdout (файловый дескриптор 1) — поток, в который программа выводит свои результаты. По умолчанию — это терминал (экран).

* stderr (файловый дескриптор 2) — отдельный поток для сообщений об ошибках. По умолчанию — тоже экран, но его можно перенаправить независимо от stdout.

Команда `ls` пишет список файлов в `stdout` → вы видите его на экране.  
Если `ls` не может прочитать каталог, ошибка уходит в `stderr` → тоже на экран, но смешиваться с обычным выводом.

### Перенаправление <a id="t_4.7"></a>
Используя символы `<, >, >>, |` можно изменить стандартные потоки.  
Для примера есть файл `main.py`, если при запуске ввести не верное имя, будет ошибка.

| Оператор | Действие                                     | Пример                         |
|:--------:|:-------------------------------------------- |:-------------------------------|
| >        | Перенаправить `stdout` в файл (перезапись)   | python3 main.py > out.txt      |
| >>       | Добавить `stdout` в конец файла              | python3 main.py >> out.txt     |
| <        | Взять `stdin` из файла                       | python3 main.py < data.txt     |
| 2>       | Перенаправить `stderr` в конец файла         | python3 main.py 2> err.txt     |
| &>       | Перенаправить и `stdout`, и `stderr`         | python3 main.py &> other.txt   |
| \|       | Передать `stdout` одной как `stdin` другой   | ls \| grep ".txt"              |

```bash
wc -l < file.txt  # программа wc считает строки не с клавиатуры, а из file.txt
echo Hello > message.txt  # вместо экрана строка попадёт в файл message.txt
# cat читает файл и пишет в stdout, grep читает из своего stdin (а это будет stdout от cat, т.к используем конвейер) и выводит только строки с "error", less принимает это и показывает постранично
cat /var/log/syslog | grep error | less
# все сообщения об ошибках отправляются "в никуда", видим только успешные результаты. /dev/null — «чёрная дыра»: всё, что туда направлено, исчезает.
find / -name "foo" 2>/dev/null 
```
