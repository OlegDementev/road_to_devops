## Магия текстовой обработки: потоки, конвейеры и фильтры <a id="t_6.0"></a>
### Философия Unix <a id="t_6.1"></a>
В Unix всё есть файл. Конфигурации — текстовые файлы. Логи — текстовые файлы. Вывод почти любой команды — текст. Даже устройства вроде жёстких дисков или клавиатуры представлены в виде файлов в каталоге `/dev`.

Программы должны общаться между собой через текст. Каждая утилита в Linux решает одну узкую задачу и делает это хорошо.  

Это и есть философия `Unix`, сформулированная ещё в 1970-х годах:

> Пиши программы, которые делают одну вещь, но делают её хорошо.  
> Пиши программы так, чтобы они могли работать вместе.  
> Пиши программы так, чтобы они обрабатывали текстовые потоки, потому что это универсальный интерфейс.  

### Конвейер (pipe) (`|`) <a id="t_6.2"></a>
Он берёт `stdout` левой команды и передаёт его в `stdin` правой. `stderr` идёт мимо, прямо на терминал. Pipe нужен тогда, когда данные рождаются на лету — из вывода другой команды, из потока, из нескольких источников.

Примеры:
```bash
ls -l | less                # длинный вывод листаем постранично
cat file.txt | wc -l        # считаем строки в файле
ps aux | grep bash          # ищем процессы с "bash"
```
