## Как учить SQL
**SQL (Structured Query Language — язык структурированных запросов)** — декларативный язык запросов, который используют для создания, обработки и хранения данных в реляционных базах данных.

На чистом SQL нельзя написать программу — он предназначен только для взаимодействия с базами данных: получения, добавления, изменения и удаления информации, а также управления доступом к ней. SQL создали в IBM в 1970-х, а в 1979 году Oracle выпустила первую коммерческую СУБД с SQL и с тех пор стал одним из ключевых инструментов для работы с данными.

## Зачем нужен SQL
Вся информация, с которой вы сталкиваетесь в интернете, содержится в базах данных. В них же хранятся данные о сотрудниках и клиентах крупных компаний, научных и социологических исследованиях, расписании рейсов ближайшего к вам аэропорта и многом другом.

Работать с этими массивами информации вручную было бы долго и непродуктивно. Поэтому придумали SQL — специальный язык для общения с базами данных.

Представьте ситуацию: женщина ищет в интернет-магазине синюю юбку стоимостью до 5000 рублей. В магазине есть 10 тысяч вариантов. Просматривать их вручную долго и сложно. Вместо этого можно воспользоваться фильтрами по категории, сезону, цвету и цене — и мгновенно получить список подходящих моделей. Это достигается благодаря языку запросов SQL.

С помощью SQL можно:
- создавать и хранить данные в виде таблиц;
- изменять содержимое и структуру этих таблиц;
- объединять разные наборы данных и выполнять вычисления;
- управлять безопасностью и контролировать доступ к информации.

Например, в крупной компании работают 500 сотрудников. 100 из них занимаются продажами и используют CRM-систему для внесения данных о клиентах, сделках и суммах. Ещё 15 IT-специалистов занимаются настройкой и обновлением этой системы. А 20 бухгалтеров регулярно выгружают сведения о платежах, счетах и документах. С помощью SQL можно предоставить каждому сотруднику доступ только к той части данных, которая ему необходима, чтобы защитить важную информацию и сохранить целостность системы.

SQL используют в Facebook, Google, Amazon, Uber, Netflix, Airbnb — практически везде. Язык нужен разработчикам, тестировщикам, аналитикам данных, администраторам, маркетологам — всем, кому по работе нужно выгружать и обрабатывать большие объёмы данных.

## Реляционные и нереляционные базы данных
Все базы данных можно поделить на два вида: реляционные и нереляционные. Язык SQL нужен для работы с первыми.

**Реляционные базы данных** — это базы, в которых данные представлены в виде таблиц. Прямо как в Excel: со столбцами, строками и ячейками. Это понятная визуализация, хотя и не совсем точная. Все таблицы в рамках одной базы данных связаны между собой.

Про реляционные БД часто говорят, что это набор двумерных таблиц. У столбцов и строк нет определённого положения. Каждый столбец диктует свой домен — тип данных, к которому могут относиться его значения. Например, в столбцах `cost` и `num_floors` могут храниться только числа, а в столбце `client` — только строки. Каждая строка должна быть уникальной и не может повторять какую-то другую строку.

Из-за этих отличий применительно к базам данных используют другую терминологию:

- **Столбец** называется **атрибутом**.
- **Строка** — **записью** или **кортежем**.

Чтобы данные не дублировались и не превращались в хранилище фейков, в реляционных БД используют **нормализацию**. При нормализации одну таблицу разбивают на несколько, а каждой записи присваивают уникальный ключ, по которому её можно идентифицировать. Всего существует шесть нормальных форм. Чем выше номер формы, тем большему количеству правил она должна подчиняться. На практике чаще всего достаточно третьей нормальной формы.

**Примеры реляционных СУБД:** PostgreSQL, MySQL, SQLite, Microsoft SQL Server, Oracle.

**Нереляционные базы данных (NoSQL)** — это базы, в которых данные хранятся не в виде таблиц, а в других форматах: документы, графы, ключ-значение. Они появились позже реляционных и решают задачи, с которыми классические таблицы справляются плохо: например, хранение больших объёмов неструктурированных данных или обеспечение высокой скорости работы при огромном количестве запросов.

SQL настолько тесно связан с реляционными БД, что все нереляционные БД в противовес стали называть NoSQL.

**Примеры нереляционных СУБД:** MongoDB, Redis, Cassandra.

## Что такое реляционная база данных?
Реляционная база данных — это тип базы данных, в котором все данные хранятся в виде связанных между собой двумерных таблиц (отношений). Слово «реляционная» происходит от английского `relation — «отношение, связь»`.  
Прежде чем начать, важно разобраться в терминах, которые часто путают.

- **SQL** — это язык (стандарт), на котором вы формулируете запросы к данным. Он одинаков почти везде. Это грамматика.
- **PostgreSQL / MySQL / SQLite / MS SQL Server / Oracle** — это **СУБД** (Системы Управления Базами Данных). Это движки, которые исполняют ваши SQL-запросы, хранят данные и следят за целостностью. Синтаксис SQL в них совпадает на 90%, но есть свои диалекты и особенности.

**СУБД** — это комплекс программ, который управляет базой данных и выполняет SQL-запросы. Она получает от пользователя команды, что нужно сделать с базой данных, и выполняют их. Эти-то команды и написаны на языке SQL.

### Краткий обзор СУБД
- **PostgreSQL:** Самый уважаемый в индустрии. Мощный, бесплатный, расширяемый. Стандарт для аналитики и бэкенда. Если учить одну СУБД — учите PostgreSQL.
- **MySQL / MariaDB:** Простой, быстрый, исторически очень популярен в веб-разработке. Именно с него начинали многие. Отличный выбор для первого знакомства.
- **SQLite:** Не требует установки и сервера — база данных живёт в одном файле. Идеален для обучения, мобильных приложений и небольших проектов. С него проще всего начать.
- **MS SQL Server:** Продукт Microsoft. Часто встречается в корпоративной среде (банки, госсектор). Синтаксис немного отличается (например, другими ключевыми словами для ограничения вывода).
- **Oracle:** Тяжёлый корпоративный стандарт. Используется в крупных энтерпрайз-системах. Для старта не нужен.

## Пара слов о DBeaver
**DBeaver** — это универсальная программа-клиент для работы с базами данных, которая позволяет подключаться к различным СУБД, просматривать структуры таблиц и выполнять SQL-запросы. Её используют практически везде. Если ознакомиться с ней во время подготовки - на работе вы не будете в ней теряться.

## Итог
SQL может показаться сложным только на первый взгляд. Если пройти пару курсов, порешать задачи в тренажёре, установить *PostgreSQL* и собрать свою первую базу данных, страх быстро улетучится. Первый же запрос, который выдаст результат, покажет, что SQL — это всего лишь удобный способ общения с данными. Освоить его можно бесплатно, а регулярная практика и понимание целей помогут закрепить навык. Начните с малого — и всё получится.
